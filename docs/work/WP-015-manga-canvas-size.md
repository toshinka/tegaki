# WP-015 漫画原稿サイズ（4960×7016）とキャンバス上限

状態: TECHNICAL COMPLETE / OWNER ACCEPTANCE PENDING。更新日: 2026-10-02。

## Goal

A4 / 600dpi 相当の漫画原稿 **4960×7016 px** を、リサイズのプリセット（**1200×1200**・**1700×2400** と並べて）から指定できるようにし、大きなキャンバスの扱いを安全に保つ。

## 変更

- リサイズpopupのプリセットに `正方形 1200×1200` / `B5相当 1700×2400` / `漫画原稿 4960×7016` を追加。
- 幅・高さの**数値入力とプリセットの上限を 8192 px**（`TEGAKI_CONFIG.canvas.absoluteMaxSize`）へ。スライダーの右端は従来の 2500 のまま（粗くならないよう、大きい値は数値入力かプリセット）。8192 は `_getMaxRenderTextureSize()`（GPUのテクスチャ上限）と同じ安全軸。
- Rasterの安全ピクセル数（従来 16Mpx 固定）を `getRasterSafePixels(canvas)` に。**キャンバス自体が大きい場合はキャンバス1枚分まで許す**（4960×7016 = 34.8Mpx）。これが無いと、キャンバス全面のRaster Layer（トーン・集中線・コマ割り・吹き出しなどの確定）が弾かれる。
- リサイズpopupに目安メモリ表示（1レイヤー ≒ w×h×4 byte。4960×7016 で約133MB）。16Mpx超は注意色で「レイヤー統合」を促す。

## 確認（Chromium・ソフトウェアGL）

- 4960×7016へ適用でき、キャンバス全面のRaster Layer作成・書き出し（原寸）・Undoが通る。ヘッドレスのソフトウェアGLでは全面レイヤー作成に約11秒（実GPUではずっと速い想定）。
- 検証: `development-harness.mjs test canvas-size`。

## 軽く扱うための案（今回は未実装・提案）

| 案 | 内容 | 効果 / 費用 |
|---|---|---|
| A. 表示プロキシ | 縮小表示時は縮小済みテクスチャ（既存の mipmap `layer-display-mipmaps.js`）で描き、確定は原寸 | 画面描画が軽い。ペン入力は原寸に直描きのまま |
| B. スパースなRaster | 全面RenderTextureではなく、描いた範囲だけの `rasterBounds` サーフェスを持つ（Layerには既に `rasterBounds` がある） | メモリが描画量に比例。空のレイヤーが大量にあっても軽い。LayerSystemの確保経路の確認が要る |
| C. Undoの差分化 | 全面スナップショットでなく `raster-patch-history.js` の領域差分を使う範囲を広げる | Undoのメモリが大幅減 |
| D. 非表示/統合の促し | 目安メモリが閾値超でレイヤー統合・ラスタライズの案内 | 実装は小さい |

次の候補は B（スパース化）と C。いずれも保存契約を変えないよう、先に確保経路と履歴のbyteSizeを調べる。
