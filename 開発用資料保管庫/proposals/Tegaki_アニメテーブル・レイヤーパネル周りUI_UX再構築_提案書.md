## 1. はじめに（背景と目的）

アニメーションテーブル（Timeline）を展開した際、右パネル（レイヤーパネル）上部のUIにおいて、以下の違和感・使いづらさが指摘された：

1. **画面の散らかりと分断（Context Fragmentation）**:
   最上部にフレーム表示パネル（`< F1 > ▶ 👻 👻`）があり、その下に `[LAYERS] [RIG]` タブがあり、その下に `CAF1 / Lane 1` が表示される。CAFとLaneがフレーム表示パネルと分断されており、情報階層が不自然。
2. **オニオンスキンの区別不能（Ambiguous Ghost Icons）**:
   同じゴーストアイコン（`👻`）が2つ並んでおり、どちらが何を意味するのか分からない。クリーム色と栗色等で違いを明示できないか。
3. **座標・整列のズレ（Misaligned Alignment）**:
   各ボタンの高さやアイコンの上下Y座標が微妙に揃っておらず、視覚的なノイズになっている。

本書は、`TEGAKI.md`、`PHASE4Z_BOUNDARY.md`、`UI_CSSスタイルガイド.md`、および過去の設計記録（`Archive/phase9m.md`）に基づき、**現行コードの物理的ボトルネックと情報設計の歪みを解明し、GPTとの相談および次期改修実装の指針となる再構築案を提示すること**を目的とする。

## 3. 現状の構造的欠陥と根本原因の解明

```text
【現状の画面構造（視覚的な分断）】
┌──────────────────────────────────────────────────┐
│  <   F1   >   ▶   👻   👻                        │ ← ① フレーム操作（.frame-indicator）
├──────────────────────────────────────────────────┤
│  [ LAYERS ]   [ RIG ]                            │ ← ② ビュー切替タブ（.layer-panel-context-view-switch）
├──────────────────────────────────────────────────┤
│  🎬 CAF1                                     👁  │ ← ③ クリップ情報（.caf-simple-group-title--flat）
│     Lane 1                                       │
├──────────────────────────────────────────────────┤
│  [ ] Layer 1                                👁 🔒│ ← ④ 内部描画レイヤー
│  [ ] 背景                                   👁 🔒│ ← ⑤ 背景
└──────────────────────────────────────────────────┘
```

### 欠陥①：CAF/Lane とフレーム操作の「分断」（歴史的経緯と包含関係の倒錯）

* **Phase 9mの設計意図**:
  `Archive/phase9m.md` およびテストコード `verify-layer-panel-frosted-focus-followup.mjs` を調査したところ、もともと上段の `.frame-indicator`（角丸 `8px 8px 0 0`）と下段の `.caf-simple-group-title--flat`（角丸 `0 0 4px 4px`）は、**「1つの磨りガラスContext Stack（二段一体カプセル）」** として設計されていた。
* **分断の発生（Phase 9nでの割り込み）**:
  Phase 9nでRIG（ボーン・変形）インスペクタを導入した際、`layer-panel-renderer.js` 内で `[LAYERS] [RIG]` タブ（`.layer-panel-context-view-switch`）が `.layer-panel-items` の先頭に挿入された。
  その結果、**一体であるはずの「フレーム操作（上段）」と「CAF情報（下段）」の真ん中にタブが物理的に割り込み、カードが真っ二つに引き裂かれた。**
* **情報階層の逆転**:
  - 本来の論理構造：
    `現在のアニメセル: 🎬 CAF1 (Lane 1)`
      ├── 時間軸（現在のコマ）: `F1` (`<` / `>` / `▶` / オニオン)
      └── ビュー切替: `[ LAYERS ]` (描画層) / `[ RIG ]` (骨・メッシュ)
  - 現行の表示構造：
    `F1 / ▶ / 👻 👻`（最上位）
      └── `[ LAYERS | RIG ]`（中位）
            └── `CAF1 / Lane 1`（最下位：しかもLAYERSタブの内部にしかなく、RIGタブに切り替えるとCAF名ごと消える！）

---

### 欠陥②：2つのゴーストの混同（時間軸 vs 空間軸の不明瞭さ）

現在並んでいる2つのゴーストアイコンは、「前フレーム」と「後フレーム」ではない：

| 要素 | ID / クラス | 正式機能 | 役割 | 現行の動作 |
| :--- | :--- | :--- | :--- | :--- |
| **左ゴースト** | `#frame-timeline-onion-btn` | **Timeline Onion** | **時間軸**の前後フレームオニオン | OFF → 1F → 2F → 3F → 4F をサイクリング（数字バッジ付き） |
| **右ゴースト** | `#frame-lane-reference-btn` | **Lane Onion** | **空間軸**の他レーン（他トラック）参照 | ON / OFF をトグル（別キャラ等の下敷き半透明表示） |

* **混同の理由**:
  1. どちらも同じ `UI_ICONS.onionSkin`（`lucide-ghost`）を使用しており、アイコン形状による区別がゼロ。
  2. 休止時はどちらも淡いクリーム背景＋茶色線画。
  3. Active（ON）になると、**どちらも同じ薄橙色（`--ui-layer-surface-focus`）に変化する**ため、違いが完全に消失する。
  4. アニメーターのメンタルモデルとしては「ゴーストが2つ並んでいる＝過去フレームと未来フレームのオニオン？」と直感的に誤読してしまう。

---

### 欠陥③：座標・アラインメントの物理的ズレ（肉眼で分かるY軸ブレ）

HTMLとCSSを精査したところ、6要素すべてのY軸中心線がバラバラになる3つの物理的原因が特定された：

```text
【座標不揃いのメカニズム（拡大図）】
  [ < ]     [ F1 ]     [ ▶ ]     [ 👻 (Timeline) ]     [ 👻 (Lane) ]
  20px      Text       18px             20px                20px
┌──────┐             ┌──────┐      ┌─────────────┐     ┌─────────────┐
│  <   │    F1       │  ▶   │      │   ┌─────┐   │     │   ┌─────┐   │
│      │  (TextBL)   │      │      │   │ 👻  │   │     │   │ 👻  │   │ ← SVG直接配置（完全中央）
└──────┘             └──────┘      │   └─────┘   │     └─────────────┘
  ↑                     ↑          │ (インライン余白)│           ↑
Flex中央               2px小       └─────────────┘        Flex中央
                                          ↑
                                  <span>内包により上に浮く
```

1. **ボタン高さの不一致（Playボタンだけ2px小さい）**:
   - `<` と `>`: 高さ `20px` (`--ui-frame-control-size`)
   - `F1`: テキスト（`padding: 2px 3px`）
   - **`▶`（Playボタン）: 高さ `18px`** (`--ui-frame-play-size`) ← **これだけ2px小さい！**
   - 👻（両方）: 高さ `20px`
2. **HTML階層構造の非対称（左のゴーストだけ上に浮く）**:
   - 左（Timeline）: `<button><span class="frame-onion-icon"><svg>...</svg></span><span class="count"></span></button>`
     - CSSで `span.frame-onion-icon` にスタイル指定がなく `display: inline`。SVGがインラインの文字ベースラインに乗るため、**下にディセンダー余白が発生し、アイコン全体が上に押し上げられる**。
   - 右（Lane）: `<button><svg>...</svg></button>`
     - SVGがボタン直下のFlexアイテムであるため、上下完全中央に配置される。
     - **結果：2つのゴーストの高さが揃わず、肉眼でハッキリと上下にズレて見える。**
3. **文字（`<` `>` `▶`）とSVGの整列基準の混在**:
   - `<` と `>` に `display: flex` のセンタリングがなくブラウザ既定のボタン文字描画。
   - `▶` はUnicode記号（文字コード）であり、フォント独自の字形偏りがある。

## 4. 再構築の基本コンセプト

### 情報アーキテクチャの再整理

```text
┌────────────────────────────────────────────────────────────┐
│ Level 1: Cel Identity & Transport (セル識別・時間・参照)    │
│          🎬 CAF1 (Lane 1)  |  < F1 > ▶ [Onion] [Ref]       │
├────────────────────────────────────────────────────────────┤
│ Level 2: Mode Switcher (このセルの表示切替)                 │
│          [ LAYERS (描画層) ]   /   [ RIG (骨・メッシュ) ]   │
├────────────────────────────────────────────────────────────┤
│ Level 3: Content Body (選択されたモードの本体)              │
│          ・LAYERS選択時: Layer 1, 背景                     │
│          ・RIG選択時   : RIGインスペクタ (Pivot, Mesh等)    │
└────────────────────────────────────────────────────────────┘
```

1. **セルの識別（CAF/Lane）とコマ（F1/再生/オニオン）の一体化**:
   「どのクリップの何フレーム目を描いているか」をヘッダーに集約する。
2. **モード切替の適正配置**:
   `[LAYERS] [RIG]` は「このセルの中身の何を編集するか」の切り替えであるため、セルヘッダーの直下に配置する。RIGを選択してもセルヘッダーは消えない。
3. **アニメテーブル収納時・展開時の連続性**:
   アニメテーブルを閉じている時でも、右パネル最上部を見れば現在のクリップ・フレーム・オニオン状態が分かり、そのまま作画・コマ送りが完結する。

## 5. UI/UX 改善提案（比較検討案）

### 案A：【統合型アニメーション・セルヘッダー】（★強く推奨）

CAFの識別情報（名前・レーン・可視性）とフレーム操作（コマ送り・再生・オニオン）を1つの洗練されたヘッダーカードに統合し、その下に `[LAYERS] [RIG]` タブを配置する。

```text
┌────────────────────────────────────────────────────────┐
│ 🎬 CAF1 (Lane 1)   👁                                  │ ← 上段: クリップ情報と可視性
│   <  F1  >   ▶   [👻オニオン]   [📄他レーン参照]        │ ← 下段: コマ送り・再生・オニオン
├───────────────────────────┬────────────────────────────┤
│          LAYERS           │            RIG             │ ← 中間: ビュー切替タブ
├───────────────────────────┴────────────────────────────┤
│ [ ] Layer 1                                      👁 🔒 │ ← 内部: 選択したタブの内容
│ [ ] 背景                                         👁 🔒 │   (RIG選択時も上のCAFヘッダーは維持)
└────────────────────────────────────────────────────────┘
```

* **メリット**:
  - 分断が100%完全に解消する。
  - 「クリップのコンテキスト（CAF1/F1）」と「編集対象（レイヤー/RIG）」の主従関係が極めて明快。
  - プロ向けアニメツール（Adobe Fresco, ToonSquid, CLIP STUDIO PAINT）のセルインスペクタ構造と合致し、直感的。
* **実装要点**:
  - `TimelineUI` の `createLayerPanelFrameIndicator()` と `LayerPanelRenderer` の `createCafReadonlyHeader()` の表示責務を整理し、DOM構造を統合ヘッダーとして構築する。

---

### 案B：【配置順序の正常化（Reordered Stack）】（最小変更案）

既存のコンポーネント構造・HTMLクラスを極力維持しつつ、パーツの挿入順序だけを正す。

```text
┌────────────────────────────────────────────────────────┐
│  <  F1  >   ▶   👻   📄                                │ ← 1行目: フレーム操作
├────────────────────────────────────────────────────────┤
│  🎬 CAF1           Lane 1                           👁 │ ← 2行目: CAF情報 (上段と直接ドッキング)
├───────────────────────────┬────────────────────────────┤
│          LAYERS           │            RIG             │ ← 3行目: タブ (CAFの下へ移動！)
├───────────────────────────┴────────────────────────────┤
│  [ ] Layer 1                                     👁 🔒 │ ← 4行目: レイヤー一覧
```

* **メリット**:
  - 変更規模が小さく、CSSの角丸結合（8px 8px 0 0 と 0 0 4px 4px）を修復し、`[LAYERS][RIG]` の挿入位置をCAFタイトルの後に移すだけで実現可能。
* **デメリット**:
  - 1行目（フレーム操作）と2行目（CAF情報）が別々のバーとして並ぶため、案Aに比べると縦の専有面積がわずかに大きい。

## 6. オニオンスキンの表現・配色改善（ユーザー提案の昇華）

### 改善方針1：アイコン形状による「時間」と「空間」の分離

「ゴーストが2つ並ぶ」こと自体を解消する：
* **Timeline Onion（時間軸）**:
  - アイコン: 現行のゴースト `👻`
  - バッジ: `1`〜`4` のコマ数表示
  - ツールチップ: `オニオンスキン (前後${count}フレーム)`
* **Lane Onion / Reference（空間軸・他レーン参照）**:
  - アイコン: ゴーストではなく、**レイヤー参照を想起させるシンボル**（例: 下敷き状の二重シート `📄`、または横レーン線入りのレイヤーマーク）
  - ツールチップ: `他レーン参照: ON / OFF`

### 改善方針2：ふたばカラーによる明示的な状態塗り分け

ユーザー様の「クリーム色と栗色に分ける」というアイデアに基づき、配色で役割を明確化する：

```text
                    【Timeline Onion（時間）】     【Lane Reference（空間）】
---------------------------------------------------------------------------------
・休止時 (OFF)    :   クリーム背景＋淡茶アイコン     :   クリーム背景＋ふたば栗色アイコン
・有効時 (ON)     :   ふたば橙面（--active-border） :   ふたば栗色面（--futaba-maroon）
                      ＋栗色アイコン                ＋背景クリーム色抜きアイコン
```

* **理由**:
  - 時間軸オニオンは、Canvas上の前フレーム描画色（栗橙 `0xd68a55`）およびアクティブ色に呼応する **「橙」** で点灯。
  - 他レーン参照は、通常レイヤーの主色である **「ふたば栗色」** の反転で点灯。
  - パレット外のニュートラルカラーを使わず、ふたば茶系＋橙の秩序の中で瞬時に判別可能となる。

## 7. 座標ズレ・アラインメントの根絶仕様（Pixel-Perfect化）

1. **ボタン高さの完全統一**:
   - `<`、`F1`、`>`、`▶`、`オニオン`、`レーン参照` の全要素を **高さ `20px`（高解像度時 `24px`）に完全統一**。Playボタンの18px変倍を廃止。
2. **Flexbox完全センタリング**:
   - 全操作要素に `display: inline-flex; align-items: center; justify-content: center;` を適用。
3. **インライン `<span>` の排除**:
   - 左ゴースト内の不要な `<span class="frame-onion-icon">` を除去（または `display: flex` 化）し、右ゴーストと全く同じFlex直下配置にして **Y座標を1ピクセル単位で完全一致** させる。
4. **Playボタン（`▶`）の視覚安定化**:
   - Unicode文字特有のフォント依存ベースラインのズレを防ぐため、`line-height: 1` の厳密化、またはSVGアイコン化を行う。

## 8. GPTへの相談・検討依頼事項（Discussion Points）

本提案書をGPTへ共有し、以下の論点について意見・分析・改善指示の作成を仰ぐ：

1. **レイアウト方式の選定**:
   - 【案A】統合型セルヘッダー（情報設計として最も美しく自然だが、`timeline-ui.js` と `layer-panel-renderer.js` の連携が必要）
   - 【案B】配置順序の正常化（低リスク・最小変更で分断を解消）
   - どちらを採用すべきか、あるいはさらなる優れた第三案があるか。
2. **Lane Onion（他レーン参照）のアイコン選定**:
   - 時間軸オニオン（`👻`）との混同を防ぐため、他レーン参照に最もふさわしいLucideアイコン（例: `layers`, `copy`, `sheet`, `film` 等）についての推奨。
3. **配色・状態表現の妥当性**:
   - ふたばパレットの制約下において、「時間軸＝橙点灯」「他レーン＝栗色反転点灯」というセマンティクスが直感的かつ視認性基準（WCAG / Tegakiスタイルガイド）を満たすか。
4. **アニメテーブル展開中と収納中における右パネルの役割**:
   - テーブル収納時（フルキャンバス作画時）でも右パネル上部でフレーム操作できる利便性を維持しながら、テーブル展開時（下部に巨大な再生バーがある時）に冗長・邪魔にならないための工夫があるか。
