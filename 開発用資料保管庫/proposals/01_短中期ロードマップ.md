# 短中期ロードマップ

更新日: 2026-08-01

## 判断の基準

1. 現行の描画、保存、History、preview / playback / export一致を壊さない。
2. 一つのPhaseでは一つの正本境界だけを拡張する。
3. Canvasを主役にし、常設UIを増やす時は頻度、発見性、touch、狭幅を同時に検証する。
4. 大きな将来案は最小MVPと停止条件を先に置き、実コード監査後にPhase化する。
5. 処理量が増える機能は、全件常駐を避けること、容量preflight、cancel / rollbackを受入条件に含める。

目的は、Quick Tool Panelと左sidebarに重複している描画toolを整理し、Canvasを広く保ちながら操作を失わないこと。

実装順:

1. QTP開閉用`Q` buttonをsidebarへ追加し、既存popupを開閉する。

5. オーナー実機で余分なtapや発見性低下がないか確認し、必要なら常用toolだけを残すPlan Bへ切り替える。

## 直近候補

- WARPのcontrol pointを矩形、円、折れ線で複数選択する。
- `square-dashed`を入口、SELECT中の`M`をshape巡回にする。BRUSH中の`M`は既存mode巡回を維持する。
- 選択shape、選択point、soft weightはruntime UI state。effect mask、Bind、topology、Project正本へ流用しない。
- Plan Bはshape segmented controlの常時表示。`M`だけでは発見できない、またはtouchでshape切替が煩雑な場合に採用する。

### B. Text to Raster

- PC優先で、文字を通常Raster Layerへ確定する最小入口から始める。
- local fontは`window.queryLocalFonts()`の明示権限またはfont file importを候補とし、`C:\Windows\Fonts`の直接走査はしない。

## 横断的な容量・性能gate

- Layer構造保持Bakeは校正済み1GiB安全上限を維持する。
- History件数だけを遅延原因と断定しない。queue delay、Project serialization、texture寿命、入力確定時間を分けて観測する。
- Perform、Mesh、DynamicsはFrame数、key数、vertex / triangle、BONE / chain、cache量の上限を計測で決める。
- previewのためにProject正本をFrameごとに書き換えない。
- simulation step、pointer sample、GPU buffer、選択overlayをHistoryやProject正本へ保存しない。
- exportとpreviewで別solver、別mesh evaluator、別motion samplerを作らない。
