## 重複を作らない境界

- Motionの時間変化は既存`ClipInstance.transformKeyframes`等の正本を拡張し、別の運動正本を作らない。
- WARPは既存deformerのBind、Pose、placement、sampling、CPU / Pixi経路を維持する。
- 任意Mesh、BONE、Perform、Dynamicsは`15`の共通評価器と所有境界を先に確定し、個別proposalを並行正本にしない。
- UI案は`14`、Rig / Mesh / Performのデータと評価順は`15`へ分離する。同じ仕様を両方へ詳細記述しない。
- WebGPUは既存CPU一致、fallback、export、device lossのgateを通るadapterだけ候補とする。

## 過去計画の扱い

- 原文は削除せず、原案、レビュー、整理前正本、解決済み調査、外部ツール参考資料へ分類した。
- 複数案は統合正本の「第一候補 / Plan B / 切替条件」に要約した。判断材料が足りない場合は原文へ戻れる。
- 過去資料から案を復活させる時は、現行コードと照合してから現行proposalへ抽出し、過去資料そのものをPhase指示書として使わない。

## 文書運用

- `tegaki_work/PROGRESS.md`は現在状態、既知残存、次の入口だけに保つ。
- 完了Phase指示書と完了診断は`Archive/`へ移す。
- 現行proposalに実装済み項目を長く残さない。必要な履歴は整理前スナップショットまたはArchiveで保持する。
- 次Phaseの実装契約は`task-codex/phase*.md`へ狭く切り出し、proposal全体を一度に実装しない。

## AI実装分担

- Sol High / XHigh: 現行コード照合、計画の分解、invariant・非対象・完了 / 停止条件の明文化。
- Luna MAX: 明示された一つのStageだけを実装し、node check、verifier、build、Browser smokeを実行。予想外の依存は推測修正せず停止報告する。
- Sol High / XHigh: diff、正本重複、state / error / cancel、undo-redo、座標、preview / Bake / export、popup順、性能を最終レビューする。

各`task-codex/phase*.md`は、Lunaへ渡す前提で目的、現状、変更対象、維持契約、非対象、設計決定、検証、停止条件、リスク、レビュー項目を含める。
