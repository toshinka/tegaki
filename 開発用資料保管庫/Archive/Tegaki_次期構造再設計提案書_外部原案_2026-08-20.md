# Tegaki 次期構造再設計提案書 — 提出要旨

本提案では、Tegakiの担当範囲を「作画・パラパラ漫画・キャラクターRig・演技制作」までと整理し、撮影・背景・小物・カメラ・エフェクト・最終動画編集についてはRemotion等へ渡せる外部境界を設ける。

中核変更は、Animation Table内に集中しているRig Setupを専用Workspaceへ段階的に分離することである。Rig Workspaceは新しいRig正本を持たず、既存のClipAsset / rigDefinition / meshDefinitions / skinBindings等を利用する。Animation TableはTiming / Motion / WARP Pose / Graph等、「いつ、どう動くか」の編集へ重点を戻す。

Rig済み素材については、最初から新しい独立Asset schemaを作らず、既存ClipAssetを参照するProject-local Rig Libraryを設ける。作画画面からRig Setupへ直接移動できる導線を作り、元Raster変更時には既存のCURRENT / STALE思想を利用して無言のRig再生成を避ける。

Remotion連携はTegaki本体への直接依存から始めず、PNG連番、preview、manifest等からなる汎用Video Handoff Packageを第一段階とする。この形式はRemotionだけでなく、Web版GPT、Claude、Codex、将来の別動画ツールにも利用可能とする。AIは制作データの橋ではなく、演技・演出相談・素材補完・自動化を担当する任意の上位層とする。

WebGPUについては全面解禁ではなく、Rig / Warpの描画負荷解消を目的とした研究Phaseとして制限を緩和する。現行CPU経路の実測を最初のGateとし、Pixi GPU Mesh / WebGL adapterとの比較を経て、WebGPU固有の利益が確認できる場合にのみ次へ進む。CPU reference、fallback、preview / export一致は維持する。

次回CODEXでは直ちに実装せず、まずArchitecture Gateを設け、現行main・ローカル正本の再確認、Rig Workspace化の可否、Animation Tableから安全に抽出できる責務、Rig Libraryのschema不要案、GPU profiling計画、Video Handoffの最小実装点、既存UI/UX再設計提案とのPhase関係を整理した上でOwnerへ返答する。
